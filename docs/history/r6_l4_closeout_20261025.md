## Supported commands and package ownership

`pyproject.toml` registers one public console entry point:

```text
sawopt = sawopt.cli:main
```

The equivalent public module entry point is `python -m sawopt.cli`. Its
commands are `validate`, `run`, `review export`, and `synthetic-task` with
`launch`, `status`, `attach`, `resume`, and `stop`. `validate` is non-executing;
`run` is a synthetic/injected-evaluator software fixture; `review export`
postprocesses an existing closed R5 raw run without evaluating or launching
work; and the countdown-task commands are synthetic software behavior only.
`python -m sawopt.synthetic_worker` is internal worker plumbing. The old
`python -m sawopt` dispatcher and `python -m sawopt export-review` are gone;
there is no compatibility alias, rejection handler, or old v1–v4 run-manifest
reader. R5's `sawopt.raw_run/1` and `sawopt.review/1` contracts do not migrate
historical runs.

The current static cross-package Python import graph at the L4 baseline is:

```text
cli               → io, optimization, reporting
optimization      → design, evaluation, io
evaluation        → design, physics
problem           → evaluation, optimization, physics
studies           → design, physics, reporting
reporting         → io
synthetic_worker  → io
physics           → physics.com (elements → com)
```

`design`, `orchestration`, and `runtime` add no cross-package source imports in
this scan; package-internal imports and Python/third-party dependencies are
omitted. This is a source import inventory, not proof about external callers.
The intentionally deferred `problem.evaluator.dense` boundary remains; the
synthetic CLI does not invoke it.
